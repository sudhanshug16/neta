# NODES.md — shared foundation for canvas directions

Read [BRIEF.md](BRIEF.md) first. This page is the mechanical reference: what
the shell gives you, what the node classes are called, and where you are
allowed to put things. Everything here is a design working file.

## Files

| file | what it is |
| --- | --- |
| `dataset.json` | The one dataset. Every direction renders it verbatim: same missions, agents, names, states, activity lines. Do not invent content, do not reorder missions. |
| `lib.mjs` | Shared drawing helpers. Import it so the same agent looks identical across artboards. |
| `shell.partial.html` | The full artboard skeleton, generated by `gen-shell.mjs`. Panels, toolbar, ground, tokens, all node classes. |
| `gen-shell.mjs` | Regenerates `shell.partial.html` from `dataset.json`. Run `node gen-shell.mjs` after touching either. |

## Starting a direction

Write `gen-<name>.mjs`. Read the shell, build your canvas markup, substitute
the two placeholders, write `<name>.dc.html`.

```js
import { readFileSync, writeFileSync } from "node:fs";
import { esc, icon, sigil, stateClass, stateColor, hueColor } from "./lib.mjs";

const data = JSON.parse(readFileSync("./dataset.json", "utf8"));
const shell = readFileSync("./shell.partial.html", "utf8");

const html = shell
  .replace("<!-- CANVAS_LAYER -->", canvas)          // your nodes and edges
  .replace("<!-- CHRONO_CONTROL -->", chronoControl); // e.g. "Oldest ← → Newest"

writeFileSync("./tidal.dc.html", html);
```

The injection point in `shell.partial.html` is exactly:

```html
  <div class="canvas-layer" style="position: absolute; inset: 0;">
    <!-- CANVAS_LAYER -->
  </div>
```

Everything you emit lands inside that `<div>`. It is `z-index: 1`; the
toolbar (7), navigator and chat (6) come later in the DOM and paint over you.
Do not touch the shell for a direction — if a direction needs a shell change,
change `gen-shell.mjs` so every direction gets it.

The chronology control is a `<span class="tb-item tb-chrono">` in the toolbar.
Put your own control inside it; keep it to one line of 12/600 text plus at most
one stroke icon.

## Coordinates

The canvas layer is 1600 × 1000, same as the window. Position nodes with
inline `left` / `top` in px so the editor's property panel can move them.

```
x:  0 ──── 280 ─────────────────────────────── 1174 ──── 1600
    │ navigator │        fully visible band        │  chat  │
y: 0
   66  ← toolbar occupies roughly x 500–1100 above this line
        (traffic lights sit at x 20–70, y 18–30)
  1000
```

- Navigator: x 16–264 (panel) — treat **x < 280** as covered.
- Chat: x 1174–1584 — treat **x > 1174** as covered.
- Fully visible band: **x 280–1174**, y 66–1000. That is 894 × 934.
- Nodes *may* extend under the panels — the canvas pans, and work continuing
  past the edge is how the composition shows there is more. The workspace
  leader, every blocked / failed / merged-not-closed mission, and anything a
  reviewer must read to judge the direction must sit fully inside the band.
- Nothing may overflow the 1600 × 1000 root. Clip at the edges instead.

## Node anatomy

All classes below already exist in the shell's `<helmet><style>`. Reuse them.
Only the Type direction may override them, and then only in its own artboard.

### `.node-agent` — an ordinary agent

```html
<div class="node node-agent" style="left: 636px; top: 430px; width: 214px;">
  <div class="node-row">
    <svg class="sigil" width="12" height="12" viewBox="0 0 12 12" aria-hidden="true">…</svg>
    <span class="node-name ell" style="flex: 1;">Iris</span>
    <span class="prov">C</span>
    <span class="access">…pencil icon…</span>
  </div>
  <div class="node-task">Return Retry-After on throttled responses</div>
  <div class="node-state state-running">
    <span class="state-dot"></span>
    <span class="state-label">Running</span>
  </div>
  <div class="node-activity">Editing src/api/middleware/limit.ts</div>
</div>
```

- Sigil from `sigil(agent.name, agent.hue)`; provider mark is `C` for Claude,
  `X` for Codex; access glyph is `icon("eye")` for read-only,
  `icon("pencil")` for read-write.
- `.node-task` carries the FULL task name. It wraps to 2–3 lines. Never
  truncate it and never drop it.
- `.node-state` takes a `state-*` class; the dot inherits `currentColor`, so
  colour the row once.
- `.node-activity` is Running only. It is on its own line so the path is
  readable; inline it into the state row only if your direction is genuinely
  tighter and you accept heavy truncation.
- Show the model (`claude-sonnet-5`, `gpt-5-codex`) wherever your direction has
  room — a 10/500 secondary line under the state row is the usual place.

### `.node-lead` — a mission lead

```html
<div class="node node-lead" style="left: 520px; top: 300px;">
  <div class="node-row">
    <span class="mono tnum lead-ord">07</span>
    <span style="flex: 1;"></span>
    <span class="mono tnum lead-age">2d</span>
  </div>
  <div class="lead-name">Rate limiter on /search</div>
  <div class="node-state state-running">
    <span class="state-dot"></span>
    <span class="state-label">Running</span>
  </div>
</div>
```

Ordinal, name, state label and age are all mandatory on every mission — that
is a hard rule, not a nicety. When `mission.attention` is set, add
`<div class="node-attn">…</div>` after the state row; that is the blocked
question, the failed check, or `Merged 2h ago, not closed`.

The lead is an agent too (`mission.lead`). Add its identity as a second
`.node-row` — sigil, name at 11/600, provider mark, access glyph — when your
direction has the space. Mission 11 has no `lead`: `leadIsWorkspaceLeader` is
true and Halden is working in it directly, so its agents hang off the leader
node.

### `.node-leader` — the workspace leader

```html
<div class="node node-leader" style="left: 690px; top: 470px;">
  <div class="node-row" style="gap: 12px;">
    <span class="leader-avatar">…crown icon at 20px…</span>
    <div style="display: flex; flex-direction: column; gap: 2px; min-width: 0;">
      <span class="leader-name">Halden</span>
      <span class="leader-sub">Workspace leader</span>
    </div>
    <span class="chip-mode" style="margin-left: auto;">Lead++</span>
  </div>
</div>
```

One per artboard. It is the focal node: give it clear space, put it where the
eye lands first, and never let a panel cover it.

### `.chip-more` — the `+N completed` expander

```html
<span class="chip-more" style="position: absolute; left: 640px; top: 690px;">
  +8 completed…chevron-right icon…
</span>
```

Show up to 8 recent completed agents per mission directly; the rest go behind
one chip. A pill with a chevron, never a bubble or a circle node. Running,
blocked and failed agents never collapse. Four missions in the dataset trip
this: 01 (+8), 02 (+1), 05 (+1), 07 (+1).

### Edges

One `<svg>` per direction, first child of the canvas layer so edges paint under
the nodes.

```html
<svg style="position: absolute; inset: 0; width: 1600px; height: 1000px;" aria-hidden="true">
  <path class="edge edge-leader" d="M 780 470 C 700 430 640 400 560 360"></path>
  <path class="edge edge-blocked" d="M 560 380 C 540 420 520 450 500 490"></path>
</svg>
```

`.edge` is stroke 1.4, round caps, violet at 35%. `.edge-leader` lifts it to
50% for leader → mission-lead links. `.edge-blocked` adds
`stroke-dasharray: 5 6` when the target is Blocked. Edges terminate at node
anchors and stay subordinate to labels and status.

### State colours

`.state-running` `.state-blocked` `.state-failed` `.state-completed`
`.state-ready` `.state-merged` `.state-idle`. Put the class on the row; the
6px dot uses `currentColor`. Colour is never the only signal — the text label
always ships with it.

## `lib.mjs`

| export | what it returns |
| --- | --- |
| `sigil(name, hue, size = 12)` | The agent's deterministic 4×4 pixel mark as an inline `<svg>`. Same name → same mark, in every direction. |
| `hueColor(i)` | Identity palette colour for hue index 0–5. |
| `hueFor(name)` / `hashName(name)` | How `dataset.json`'s `hue` was assigned. You normally read `agent.hue` instead. |
| `stateColor(state)` | Hex for a state string, including `"Merged · not closed"`. |
| `stateClass(state)` | The `state-*` class name for that state. |
| `stateShort(state)` | `"Ready"`, `"Merged"` — for rows too tight for the full label. |
| `esc(text)` | HTML-escape. Run every dataset string through it. |
| `icon(name, size = 12, color = "currentColor")` | Stroke SVG string. Names: `crown`, `eye`, `pencil`, `question`, `x`, `check`, `merge`, `chevron-down`, `chevron-right`, `stop`, `fit`, `minus`, `plus`, `dot`, plus `clock` and `arrow-up` used by the shell. |
| `TOKENS` | The colour tokens, if you need one in JS. In CSS use the custom properties on the root div (`var(--mint)`, `var(--violet)`, `var(--text-2)`, …). |

## Density target

At the mockup's zoom, 7–10 missions must be readable **with their agents**, and
the remaining missions must be visibly present — continuing past the edge,
receding, or compressed — never absent. All 14 open missions are on the canvas.
104 agents plus 13 mission leads: per mission 16, 11, 8, 5, 11, 4, 11, 7, 3, 9,
8, 5, 4, 2 for ordinals 01 → 14.

Both halves of the balance are requirements. A sparse graph of small circles
reads as an architecture diagram; a wall of cards and bubbles reads as a
novelty. Nodes stay clickable and fully labelled, and the composition itself —
not a legend — has to make the flow of work feel temporal.
